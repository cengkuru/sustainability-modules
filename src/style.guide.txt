## Design Philosophy

This styleguide embodies the principles of Dieter Rams' functionalist approach with Jony Ive's premium material sensibility:

-   **Less, But Better** - Remove everything that isn't essential
-   **Honest UI** - Elements clearly communicate their function
-   **Unobtrusive** - Interface recedes to highlight content
-   **Precise** - Meticulous attention to alignment, spacing, and proportion
-   **Timeless** - Avoids trends in favor of lasting utility and clarity
-   **Premium Material Feel** - Digital materials behave with integrity, incorporating subtle gradients and transparency.

## Color System

The color system uses a minimalist palette focused on light backgrounds, clear typography, and selective use of accents and transparency.

Color Usage

Backgrounds: Primarily use var(--white) or light gradients (e.g., linear-gradient(to bottom, var(--neutral-50), var(--white))). Consider subtle transparency effects (rgba(255, 255, 255, 0.9)) for "frosted glass" overlays where appropriate.

Text: Use var(--neutral-700) for primary text/headings and var(--neutral-500) for secondary text. Ensure high contrast (at least 4.5:1).

Primary Actions: Use var(--black) for primary button backgrounds with var(--white) text.

Accent Usage: Use var(--accent-color-base) (Teal Blue) for focus indicators, active tabs/selections, and potentially accent text where needed.

Status Indicators: Use the specific --status-* colors for their semantic meaning.

Borders & Dividers: Use var(--neutral-300) and var(--neutral-200) respectively for subtle separation.

Hover States: Use subtle shifts, like var(--neutral-100) for light backgrounds or var(--neutral-800) for black elements. Button hovers might use accent colors or gradients (see component definitions).

Icons
Icon Sizes

Small: 16px

Medium: 20px

Large: 24px

Icon Style

Use clean, simple line icons with a 1px or 1.5px stroke width.

Keep icons monochrome, typically inheriting currentColor to match text color (var(--neutral-700) or var(--neutral-500)).

Use consistent rounding (e.g., 2px radius) if applicable to the icon set.

Design Implementation Guidelines
1. Component Hierarchy

Maintain a logical hierarchy: Layout -> Sections -> Components -> Elements.

2. Responsive Behavior

Mobile-first approach.

Use relative units (rem).

Test at key breakpoints (320px, 768px, 1024px, 1440px).

3. Accessibility Considerations

Maintain minimum 4.5:1 contrast for normal text, 3:1 for large text. Check contrast especially for var(--neutral-500) on white/light gray.

Ensure keyboard navigability and focus visibility (:focus-visible).

Use semantic HTML.

Provide text alternatives (alt text, aria-labels).

4. Implementation Notes

Consider using a utility-first CSS framework (like Tailwind CSS) and configuring its theme to match these variables.

Implement the background gradient (from-gray-50 to-white) on the main body or layout containers.

Use transparency utilities (e.g., bg-white/90, bg-white/40) for frosted glass effects where needed.

Create reusable components.

Document component usage.

Adapting Colors (Notes on this Adaptation)

This version of the style guide has been adapted based on the provided palette:

Neutrals: Replaced with a white/light gray base and specific dark/medium gray text colors (#111827, #4B5563).

Accents: Primary button actions now use black. The general UI accent (focus, active states) uses the specified 'Active' status color (#61a8bd).

Functionals: Status colors (#61a8bd, #4CAF50, etc.) were added and mapped to functional roles like --alert, --success, --info.

Transparency/Gradients: Incorporated the concepts of background gradients and transparent UI elements into the usage guidelines and component descriptions.

Contrast: Color choices were made aiming for sufficient contrast, but always verify in implementation, especially var(--neutral-500) text.
